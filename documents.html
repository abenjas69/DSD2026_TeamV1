MEETING NOTE

S2 Upstream Data Context

Record of the early sensor-data discussion, kept as upstream context for future richer interfaces.

Original data questions

V1 identified the data that would be useful for a richer motion-recognition pipeline:

  • Measured sensor data or motion stream.
  • Timestamp or sequence information.
  • Sensor or joint identification, if available.
  • Payload format and units defined in IF1.
  • Payload status and error information.
  • Target angle or expected values used for comparison.

S2 response

S2 confirmed that sensor-side data can be provided, but explained that the expected target angle may not belong to S2 and may instead be stored in the V2 database.

  • Confirmed by S2 Measured data, timing or sequence information, identifiers when available, format and units, and payload status or error information can be provided as upstream sensor context.
  • Ownership note Target angle or expected values should be confirmed through V2, because V2 is the direct integration point for V1.

Current V1 follow-up

  • Generation 1 Use V2 as the official V1 data source and output destination.
  • V1-V2 Work with the current V2 API using jointAngles, isCorrect, timestamp, and sessionId.
  • Future extension Revisit targetAngles, sensorData, and errors with V2 after Generation 1.
