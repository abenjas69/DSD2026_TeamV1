FEATURED UPDATE

V1-V2 Interface Alignment for Generation 1

2026-05-05

Team V1 discussed the interface with Team V2. V2 confirmed that the current production API still uses jointAngles, isCorrect, timestamp, and sessionId.

V2 also explained that changing endpoints now could risk breaking Generation 1 integration. Team V1 agreed to work with the current API for Generation 1 and send recommendation results through POST /recommendations.

The richer IMU-based schema using targetAngles, sensorData, and errors remains planned for a future generation. This future schema is important for a more complete AI and motion-recognition pipeline, but it should be revisited after the current presentation.

INTERFACE

Current V2 API confirmed

V2 confirmed that targetAngles, sensorData, and errors are not implemented in the current production API yet. They remain part of the future interface direction.

DOCUMENTS

Requirement Analysis v1.4 updated and published

The Requirement Analysis was updated to reflect V2 as the direct V1 input and output point. Version 1.4 also clarifies that Generation 1 uses two angle values inside jointAngles and produces a plain-text recommendation through V2.

2026-05-06

ROADMAP

Generation 1 and future extension strategy clarified

Generation 1 will use jointAngles + isCorrect + timestamp + sessionId. The future extension may use targetAngles + sensorData + errors after V1 and V2 revisit the API. Version 1.4 clarifies that the immediate input is a two-angle workflow and not a full IMU pipeline yet.
